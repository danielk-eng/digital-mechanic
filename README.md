# Цифровой механик — AI-агент диагностики ДВС (ИИкузница 2026, НейроДВС)

Веб-чат для механика на посту ТО (работает с телефона). Механик выбирает машину и проверку, агент берёт
результат из ML-сервиса, объясняет его простыми словами, отвечает на вопросы **только по руководствам на
двигатель этой машины** со ссылкой на страницу PDF, составляет заявку на дефектовку и отправляет её в ТОиР
после подтверждения механика. Есть режим главного механика (сводка по парку), голос, фото, 6 языков.

## Запуск за 5 минут

### Docker (рекомендуется)
```bash
cp .env.example .env          # вписать LLM_API_KEY (и, по желанию, DEEPGRAM_API_KEY)
docker compose up -d --build  # официальные заглушки ML (8001) и ТОиР (8002) + приложение
# открыть http://localhost:8000   (главный механик: http://localhost:8000/manager)
```
### Без Docker (Python 3.11+, Linux/macOS)
```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
cp .env.example .env          # вписать LLM_API_KEY
scripts/run_local.sh          # заглушки 8001/8002 + приложение на :8000 (PORT=8010 scripts/run_local.sh — другой порт)
```
Windows (PowerShell): `pip install -r requirements.txt`, затем в трёх окнах из `vendor/neurodvs_mock`:
`uvicorn mock_ml.app:app --port 8001`, `uvicorn mock_toir.app:app --port 8002`, и из корня
`$env:PYTHONPATH="src"; uvicorn digital_mechanic.web.app:app --port 8000`.

PDF руководств в репозитории нет (текстовый индекс страниц уже собран в `data/index/`). Чтобы показывать
картинки страниц, скачайте PDF из папки Заказчика: `python scripts/fetch_manuals.py` → `data/manuals/`.
Без ключа LLM приложение работает в упрощённом режиме: вердикт, найденные страницы, заявка по шаблону.

## Сценарии защиты
| | Что сделать | ТС / проверка |
|---|---|---|
| С1 | Выбрать ТС → «Получить результат диагностики» → «Создать заявку» → «Подтвердить» | M333YK47 / S-0005 (F08) |
| С2 | Спросить «Можно ли своим ходом перегнать машину на базу?» | там же |
| С3 | Проверка со сбоем записи — агент просит перезаписать, заявку не создаёт | P456AT178 / S-0003 |
| С4 | `/manager` → «Карантин» → ТС → история проверок и график | любой из карантина |

Прогон из консоли: `python scripts/e2e.py http://127.0.0.1:8000`, контрольные вопросы RAG: `python scripts/rag_probe.py`.

## Архитектура
```
Браузер (index.html — механик, manager.html — главный механик)
   │  REST /api/*
FastAPI (web/app.py) ── журнал, согласие, маскирование ПДн, голос (voice.py)
   │
Агент (agent/core.py): LLM с tool calling, сам выбирает инструмент
   ├─ get_diagnosis        → ML-сервис  POST /diagnose          (clients.py, URL из .env)
   ├─ search_manual        → BM25 по страницам руководств ТОЛЬКО двигателя этого ТС (retrieval/bm25.py)
   ├─ get_vehicle_history  → проверки, заявки, ремонты по vehicle_id (B1, store.py — SQLite)
   ├─ prepare_ticket       → черновик заявки; цитаты проверяются по странице, приоритет считает код
   ├─ start/update_repair  → пошаговый ремонт («готово», «повтори» — в том числе голосом)
   └─ search_extra_docs    → доп. руководства по автомобилю (МАЗ), только по марке ТС, метки [X#]
Политика (policy.py, детерминированно): сбой записи → только перезапись; норма → без заявки;
отклонение → заявка по подтверждению; низкая уверенность / предупреждение качества → сначала осмотр узла.
Заявка уходит в ТОиР (POST /tickets) только после кнопки «Подтвердить».
```
Защита от выдуманных цифр (`agent/grounding.py`): каждое число в ответе должно найтись на страницах,
которые агент реально открыл в этом разговоре, иначе ответ переписывается, а при повторе предложение вырезается.
Нормативы другого двигателя не попадают в контекст вовсе — фильтр по модели двигателя стоит до ранжирования.

| Модуль | Роль |
|---|---|
| `schemas.py`, `adapters.py`, `clients.py` | Контракты ML/ТОиР v6 (имена полей — один файл), HTTP-клиенты |
| `policy.py` | Исходы F3, приоритет low/medium/high с обоснованием, статусы парка |
| `ingest/pages.py`, `retrieval/bm25.py` | Постраничный индекс PDF (pdftotext/pypdf), BM25 со стеммингом |
| `agent/` | LLM-клиент, промпты, инструменты, проверка ответа |
| `store.py`, `pii.py` | SQLite (пользователи, проверки, заявки, ремонты, переписка, аудит), маскирование ПДн |
| `i18n.py`, `web/static/i18n.json` | ru, uz, tg, kk, hi, vi |
| `voice.py` | STT: Deepgram nova-3 → faster-whisper (если установлен) → распознавание браузера; TTS: браузер или Silero |

## Настройки (.env)
| Переменная | Назначение |
|---|---|
| `ML_SERVICE_URL`, `TOIR_SERVICE_URL` | Адреса ML-сервиса и ТОиР (F6). Подставить рабочие — больше ничего менять не нужно |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | Любой OpenAI-совместимый API. По умолчанию TokenRouter, `deepseek/deepseek-v4.1-flash-1017-free` |
| `LLM_THINKING` | `off` (по умолчанию) — без «размышлений», ответ в 3–4 раза быстрее (10–20 с) |
| `DEEPGRAM_API_KEY` | Голосовой ввод (необязательно; без ключа — распознавание браузера) |
| `SILERO_ENABLED` | Локальный синтез речи (нужен torch); иначе — синтез браузера |
| `COMET_API_KEY` | Трассировка в Opik (необязательно, `pip install opik`) |
| `PII_MASKING`, `REQUIRE_CONSENT`, `AUDIT_RETENTION_DAYS` | 152-ФЗ, см. `docs/152-ФЗ.md` |

Секреты — только в `.env` / переменных окружения, в репозиторий и логи не попадают.

## Голос и языки
Микрофон в чате: запись с автоостановкой по тишине → `/api/stt`. Deepgram nova-3 поддерживает ru, uz, kk, hi, vi;
таджикский Deepgram не распознаёт — для tg используется распознавание браузера (или faster-whisper, если установлен).
Ответы можно озвучивать; режим «руки свободны» читает ответ и снова включает микрофон.
Язык интерфейса и ответов выбирается при входе; руководства русские, поэтому цитаты и названия документов остаются на русском.

## База знаний
Шесть PDF Заказчика (ЯМЗ-236М2 РЭ и РК, ЯМЗ-536 РЭ и РК, ЗМЗ-5234.10 РК, ЗМЗ-40904/40905.10), 1743 страницы, номера страниц — по PDF.
Соответствие «двигатель → документы» и обозначения документов как в ТЗ — `data/engine_docs.yaml`.

**Дополнительная база (необязательно, `EXTRA_KB_ENABLED`)**: руководство по эксплуатации автомобилей МАЗ 6422 и др.
(источник — maz-ptc.ru, 320 страниц). Используется только как справка по автомобилю той же марки, никогда — для
нормативов двигателя и ссылок в заявке. Руководство КАМАЗ 4350/5350/6350 из исходной сборки **исключено**: PDF был с
неофициального зеркала (avtoalfa.com), права на распространение не подтверждены; загрузчик отбрасывает этот источник,
даже если он окажется в файле индекса (`retrieval/bm25.py`, тест `test_kamaz_mirror_excluded`). Машин КАМАЗ в парке нет.

## Журнал и данные
SQLite `var/app.db` (WAL) и `var/app.log.jsonl`: кто, когда, по какой машине, какие инструменты и источники, время,
токены. Главный механик видит журнал во вкладке «Журнал», выгрузка — `/api/audit.csv`. Расход LLM — `/api/usage`.
