# Видео: один дубль ≤ 2:50 (запись V на deb, 27.11)

Заменяет [ВИДЕО_СЦЕНАРИЙ_3МИН.md](ВИДЕО_СЦЕНАРИЙ_3МИН.md) и прежние сцены А–В. Один непрерывный дубль на стенде deb, без монтажа склеек: ожидание ответа модели не вырезаем, а ускоряем (`scripts/video_speedup.sh`), поэтому на экране видно, что всё работает вживую. Машины и сессии — из данных хакатона. Поведение закреплено автотестами (`tests/test_organizer_rules.py`) и прогоном `scripts/demo_rehearsal.py dryrun`.

27.11 записан автоматический черновой дубль 2:08: `scripts/record_demo.py` управляет актуальными mobile/desktop shells на `http://127.0.0.1:18610`, `scripts/video_narrate.py` добавляет черновую TTS-озвучку. Итог: `runs/video_full/digital_mechanic_demo_narrated.mp4`, копия рядом с репозиторием `../digital-mechanic-demo-2026-11-27.mp4`. Это уже не OBS-инструкция, а проверяемая автоматическая запись; для финальной сдачи желательно просмотреть её целиком и при необходимости заменить TTS живым голосом по таймлайну ниже.

## Подготовка (за 10 минут до записи)
1. На deb, в `stand/app`: `bash scripts/demo_db.sh restore video` — база в состоянии «перед дублем»: начатый Ивановым А. ремонт E549YT198 (шаг 3 из 9), заявок от прошлых прогонов нет. Перед каждым повторным дублем — снова `restore video`.
   Если снимка нет: `restore clean`, затем с box `python scripts/demo_rehearsal.py prep --url <стенд>`, затем `bash scripts/demo_db.sh backup video`.
2. Прогрев (первый ответ модели после простоя медленнее): `python scripts/demo_rehearsal.py dryrun --url http://127.0.0.1:18610`, потом опять `restore video`.
3. Записывать с `http://127.0.0.1:18610` (без туннеля: адрес trycloudflare может смениться, микрофон на localhost разрешён браузером).
4. Chrome, окно 1920×1080, масштаб 100 %. Для части механика — DevTools → Device toolbar → 390×844 (iPhone 12 Pro), DevTools прикрепить к отдельному окну, чтобы не попадало в кадр. Для главного и инженера — Device toolbar выключить (Ctrl+Shift+M).
5. Запись экрана: OBS Studio (`sudo apt install obs-studio`), источник «Захват окна (Xcomposite)» → окно Chrome, 1920×1080, 30 fps, формат mkv, звук — микрофон (вопрос голосом произносится в кадре). Без OBS: `ffmpeg -f x11grab -framerate 30 -video_size 1920x1080 -i :0.0 -f pulse -i default -c:v libx264 -preset ultrafast -crf 18 -c:a aac take.mkv`.
6. Секундомер или маркеры OBS (горячая клавиша «Добавить метку главы»): отмечать начало и конец каждого ожидания — они нужны для ускорения.

## Ускорение ожиданий
```bash
# сегменты START-END:FACTOR в секундах сырого дубля (по меткам OBS), пример:
scripts/video_speedup.sh take.mkv digital_mechanic_demo.mp4 "9-56:4" "64-80:3" "90-118:5" "121-130:3" "147-162:5" "193-216:5"
```
Скрипт оставляет обычные куски как есть (со звуком), ускоренные — без звука, собирает H.264 + AAC, 30 fps, ≤ 1080p, `faststart`. Проверен на тестовом ролике: 60 с с двумя сегментами (×6, ×2,5) → 29 с.

## Рискованные шаги
1. Объяснение вердикта — 43–51 с. Единственный долгий шаг; в ролике ×4. Если ожидание > 60 с (сработает сторож и покажется ошибка) — `restore video` и дубль заново.
2. Голосовой вопрос: распознавание идёт на CPU deb (7–8 с); говорить чётко, микрофон близко. Если распознано не то — стереть и ввести текстом, в ролике это допустимо.
3. Ответы модели меняются от прогона к прогону. Стабильно (проверено двумя прогонами): ссылки на 236-3902150-Б с. 31 и РК с. 254, карточка противоречия, отказ при 0,48, расхождение F08 (они решаются кодом, а не моделью). Вопрос вне руководства: формулировка «нет» распознаётся шире после исправления `_NO_DATA`; если модель всё же ответит иначе, плашка «пробел в базе» у главного не появится — тогда показать её по записи из прогона.
4. Продолжение ремонта видно только после `restore video` (снимок содержит начатый ремонт). Дата отметки — 27.11, не «вчера».
5. Бесплатная модель может ответить 429 или с задержкой; стенд переключится на резерв, ответ будет дольше. Перед дублем прогрев (п. 2 подготовки).

## Не показываем в ролике (нереализовано)

- оформление дефектовки внутри продукта (только текст рекомендации);
- потоковая диагностика звука и запись звука двигателя приложением (берём результаты ML-сервиса);
- обязательное фото положения микрофона;
- OCR таблиц-картинок в PDF;
- руководства вне материалов задачи (КАМАЗ исключён);
- локальный режим на GPU (подготовлен, на этом железе не запускался);
- публикация приложений в магазинах.
