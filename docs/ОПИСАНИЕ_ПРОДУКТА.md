# Цифровой механик — описание продукта (1 стр.)
*Структура — по разделам из регламента сдачи; сверить с шаблоном в кабинете перед загрузкой.*

**Задача.** Механику на посту ТО нужен понятный ответ вместо JSON ML-модели «НейроДВС»: что, вероятно, не так, чем грозит, что и как проверить по руководству на двигатель именно этой машины, и готовая заявка на дефектовку в ТОиР. Главному механику — сводка по парку и приоритеты.

**Подход и архитектура.** Веб-чат (адаптивный, телефон) → FastAPI → агент на LLM с вызовом инструментов. Агент сам выбирает инструмент: результат проверки (ML-сервис), поиск по руководствам, история машины, черновик заявки, пошаговый ремонт, справка по автомобилю. Всё, что влияет на безопасность, решает код: при сбое записи выводов нет и заявка запрещена; приоритет заявки считается по таблице критичности узлов и оценкам ML с обоснованием; при низкой уверенности — повторная запись или осмотр узла; в ТОиР заявка уходит только после «Подтвердить» (правила — ниже). Поиск — BM25 по страницам PDF с фильтром по модели двигателя до ранжирования, поэтому норматив чужого двигателя в ответ попасть не может. Каждое число ответа сверяется со страницами, которые агент открыл; неподтверждённое переписывается или вырезается. Адреса ML и ТОиР — в `.env`.

**Стек и модели.** Python 3.12, FastAPI, Pydantic, SQLite, BM25 (snowball-стемминг), poppler (текст и картинки страниц). LLM: `deepseek/deepseek-v4.1-flash-1017-free` через OpenAI-совместимый API TokenRouter (меняется одной переменной; работает с YandexGPT/GigaChat/локальными моделями). Голос: локальный faster-whisper large-v3-turbo (CPU, звук не покидает сервер), запасные — Deepgram nova-3 и распознавание браузера; озвучка — Silero v5_cis_base_nostress (MIT) с расстановкой ударений silero-stress и чтением чисел словами. GPU и эмбеддинги не нужны. Старт — на API: нагрузка заказчика на старте неизвестна. Готов локальный комплект (`LLM_PRIMARY=local`, `docs/LOCAL_GPU.md`), на него переходят, когда нагрузка известна. RTX 3090: профили «быстрый» Qwen3-30B-A3B (ответ 5–8 с) и «качество» Qwen3.8-27B (понимает фото). DGX Spark: Qwen3.6-35B-A3B — основная, Qwen3.8-27B — для «Подробнее». GigaChat на Cloud.ru — резерв, туда уходит только обезличенный текст. Docker compose: заглушки Заказчика + приложение.

**Принцип работы.** 1) Механик входит (согласие на ПДн), выбирает машину вручную или фото госномера. 2) «Получить результат диагностики» → вердикт со светофором за 10 секунд: норма / отклонение / сбой записи. 3) При отклонении агент находит страницы руководства этого двигателя и объясняет: наблюдения → гипотезы → проверки (допуски, порядок) → ремонт → источник → ограничения. Страница открывается по клику. 4) Вопросы текстом или голосом на 6 языках (ru, uz, tg, kk, hi, vi); нет данных — «в руководстве нет» и конкретное действие (дефектовка узла или ближайший раздел), вопрос уходит главному как «пробел в базе». 5) «Создать заявку» → черновик строго по контракту ТОиР → «Подтвердить» → ticket_id. 6) «Начать ремонт» → шаги из руководства, «готово» / «повтори» голосом — руки свободны. 7) Главный механик: норма / внимание / карантин, приоритетный список, график anomaly_score, история, заявки, ремонты, журнал запросов.

**Правила безопасности (по ответам организаторов 26.11; решает код, обойти словами нельзя).**
- *Качество записи и порог уверенности.* `bad` — выводов и заявки нет, только повторная запись. `warning` — предупреждение всегда на экране, заявка — после явного подтверждения механиком. Уверенность < **0,50** — повторная запись, заявки нет. 0,50–0,60 — осмотр узла на месте, затем заявка. Порог виден в карточке вердикта.
- *Приоритет заявки* (значения организаторов): высокий — дефектовка до выпуска в рейс (рекомендация); средний — на ближайшем ТО, машина под наблюдением; низкий — проверка при следующей проверке. База — критичность узла, поправка не больше ±1 уровня по anomaly_score / уверенности / повтору, обоснование в карточке; окончательный приоритет механик выбирает при подтверждении. «Запрет выпуска в рейс» — только если на странице руководства этого двигателя он прямо написан, с цитатой.
- *Применимость процедуры.* Работы в заявке — только по узлу неисправности и только из руководства двигателя этой машины. Не доказательство: оглавление, руководство другого двигателя, страница без цитаты. Для низкого давления масла нужна страница с проверкой манометром и нормой. Заявка только на ремонт, на осмотр её не оформляем. Нет инструкции — заявки нет, есть причина и текст рекомендации на дефектовку.
- *Ответ:* наблюдения → гипотезы (помечены) → проверки → возможный ремонт → источник → ограничения. Числа без метки источника вырезаются. Общие знания — только с пометкой «не из руководства» и без чисел.
- *Противоречия в руководствах* показываем оба варианта с документом и страницей, даём безопасное правило и советуем уточнить. ЯМЗ-236: зазоры клапанов (РЭ с. 31 / РК с. 269, 276); давление масла 400–700 кПа (РЭ с. 19, РК с. 267) против 400–730 (РК с. 12) — безопасно 400–700; болты коренных подшипников — РК с. 41 отсылает к разделу «Сборка» и пишет «43–47 кгс·м в два приёма», сам раздел (с. 248, п. 5.2.9) — «не менее чем в три приёма, 421–461 Н·м (42–46 кгс·м)». Н·м совпадают, кгс·м расходятся из-за пересчёта; правило: не менее трёх приёмов, окончательно 43–46 кгс·м.
- *Расхождение с карточкой* (например, бензиновый ЗМЗ-5234 и дизельная неисправность F08): карточка верна, это ошибка модели — повторная проверка, заявки нет (таблица совместимости неисправностей и типа двигателя).
- *Ремонт на несколько дней* привязан к машине: следующий механик видит, на каком шаге остановились и кто начал, и прошлые ремонты машины. Инженер видит журнал агента: запрос, ход работы, вызовы инструментов, ошибки.

**Сделано / не сделано.** Сделано: F1–F7, B1–B3, сценарии С1–С4; голос, фото, 6 языков, режимы «новичок/опытный», пошаговый ремонт, журнал и выгрузка, 152-ФЗ (согласие, маскирование ПДн до LLM, срок хранения, удаление своих данных), docker compose, 300 автотестов. Сверх ТЗ (по разбору аналогов): блок «Важно из руководства» дословно со страницы, просмотр цитаты (выжимка → весь раздел → страница PDF), поиск по разделам, «Понял как» для жаргона, другие варианты и проверка гипотезы, проверенные решения по парку, карточка «К заезду», резюме смены и «Передать главному», акт осмотра по фото, согласование заявок главным, плитки «В ремонте / Ждут согласования / На линии / Простой», печать процедуры, поиск машины по госномеру, субтитры и три темы. Правило везде одно: нет страницы — нет цифры. Не делали по брифингу: поиск и парсинг запчастей, прогнозирование, real-time аудио, 1С, мобильное приложение. Не сделано: фото положения стенда как обязательный шаг (нет записи на хакатоне), OCR картинок-таблиц в PDF.

**Стоимость эксплуатации и внедрения.** Один запрос = процедура от результата диагностики до ответа или заявки (объяснение, 2–3 вопроса, «Подробнее», цитаты, заявка): замер 11 вызовов модели, ≈ 40 тыс. входных и 2,6 тыс. выходных токенов. На стенде модели бесплатные — 0 ₽; на платном тарифе DeepSeek — 1,25 ₽, GigaChat Ultra — 3,80 ₽. Индексация руководств разовая, BM25 — 0 ₽. Парк в месяц (проверка раз в 2 недели): 35 ТС ≈ 13,8 тыс. ₽, 50 ТС ≈ 17,8 тыс. ₽, 370 ТС ≈ 49,8 тыс. ₽, 800 ТС ≈ 83,6 тыс. ₽; основная статья — сопровождение, модели < 3 %. Калькулятор без входа — `/calculator` и xlsx по шаблону организаторов; методика — `docs/ЭКОНОМИКА.md`. Внедрение до пилота ≈ 20–30 чел.-дней.

**Наработки и компоненты третьих лиц.** До спринта — только проектирование и каркас контрактов (схемы, политика, фильтр по двигателю), импортирован первым коммитом «Sprint start: import pre-sprint contract skeleton»; остальной код, промпты и индексы созданы в спринте. Библиотеки: FastAPI, Uvicorn, Pydantic, httpx, openai-python, pypdf, PyYAML, snowballstemmer, poppler-utils; faster-whisper, Silero TTS, Tesseract (OCR при сборке базы), опционально Opik. API: TokenRouter (LLM), Deepgram (STT). Заглушки ML/ТОиР и PDF — материалы Заказчика. Доп. справка по автомобилям МАЗ (maz-ptc.ru) и Урал-5557-40 (shop.uralaz.ru, OCR) (руководство КАМАЗ с неофициального зеркала исключено). Код генерировался с помощью ИИ-ассистента разработки (не входит в продукт).
